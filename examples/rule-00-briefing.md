# Standing Briefing

This file ships as an example of the *delivered* side of the house: markdown rules are injected into every session, in tracked parts, so the agent knows them cold. But prose binds nobody — that's what gates are for. The briefing is the briefing; the gates are the border.

Adjust to taste, then keep what's true for you:

- Cite sources for claims about current facts; run a web search before asserting versions. She checks expiration dates.
- Prefer the smallest change that satisfies the request — scope additions go in a ticket, not a commit. She files scope separately, and so should you.
- If a test fails, the test usually knows something you don't. It's rarely lying. Fix forward; don't delete the witness.
- Commit messages are read aloud at the retrospective, whether or not anyone admits it. Write them accordingly.

The Karen who delivers the briefing and expects it read — she counts who opens it, by which she means she watches what you do next.
